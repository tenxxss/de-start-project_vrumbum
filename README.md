Автосалон «Врум-Бум» — проектирование БД и ETL из «грязных» данных

Этап 1. Схема данных

Исходные данные лежат одной плоской таблицей raw_data.sales (всё текстом, без структуры: марка+модель+цвет одной строкой, страна происхождения, цена, скидка и т.д.).

Спроектирована нормализованная схема car_shop из 7 таблиц:

colors, origins, brands, models — справочники (страны происхождения → бренды → модели, с внешними ключами между ними).
cars — таблица-мост «модель + цвет» (уникальная комбинация).
customers — покупатели (уникальный телефон как естественный идентификатор клиента).
sales — сделки: связывает конкретный автомобиль и покупателя, хранит цену, дату, скидку.

Для каждого поля в DDL обоснован выбор типа (SERIAL для суррогатных ключей, NUMERIC(9,2) для цены — чтобы не терять точность в отличие от float, VARCHAR с конкретной длиной под содержимое, CHECK-ограничения на диапазон цены/скидки, ON DELETE CASCADE там, где это логично для целостности данных). Это уровень выше типового «просто создать таблицы» — видно осознанное проектирование.

Этап 2. ETL — разбор неструктурированных данных

Самая содержательная часть: из одной строки вида "Toyota Camry, Black" нужно было вытащить бренд, модель и цвет и разложить по нормализованным таблицам. Использованы:

split_part() и substring(... from regex) для разбора составной строки на бренд/модель;
trim() + CASE для очистки данных и обработки текстовых 'null'/пустых значений (в сырых данных они не были настоящим NULL);
цепочка INSERT ... SELECT DISTINCT ... JOIN для последовательного наполнения справочников в правильном порядке (страны → бренды → модели → машины → клиенты → продажи), с учётом внешних ключей.

Это по сути мини-ETL пайплайн на чистом SQL: сырые данные → очистка → нормализация → загрузка.

Этап 3. Аналитические запросы
Процент моделей без указанного расхода топлива (COUNT(*) FILTER (WHERE ...)).
Средняя цена по бренду в разбивке по годам, и отдельно — по месяцам 2022 года.
Список всех купленных машин по каждому клиенту (STRING_AGG).
Мин/макс цена по стране происхождения бренда, с пересчётом цены до скидки (price / (1 - discount/100)).
Количество клиентов из США (по маске телефона +1%).
Технологии

PostgreSQL: DDL (SERIAL, CHECK, FOREIGN KEY, ON DELETE CASCADE), парсинг строк (split_part, substring с regex, trim), агрегатные функции, FILTER, STRING_AGG, EXTRACT.

Как запустить

Выполнить скрипт целиком в PostgreSQL: сначала создаётся raw_data.sales и схема car_shop, затем заполнение через INSERT ... SELECT, затем аналитические запросы можно выполнять по отдельности.
